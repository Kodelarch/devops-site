О чём урок

ℹ️Зачем это нужно

Все следующие уроки (2.2 и дальше) написаны в предположении, что ты уже понимаешь, что такое переменная, цикл, функция и класс. Если раньше не программировал — начни отсюда. Это не про DevOps, это про сам язык: кирпичики, из которых потом строится всё остальное.

📘Словарик на будущее
  • Интерпретатор — программа, которая читает твой код построчно и сразу его выполняет (в отличие от компилятора, который сначала переводит весь код в машинный, и только потом запускает).
  • Переменная — имя, под которым в памяти хранится значение; можно менять, что под этим именем лежит.
  • Тип данных — какого рода значение хранится (число, текст, список и т.д.) — от типа зависит, какие операции с значением вообще возможны.
  • Область видимости (scope) — часть кода, где конкретная переменная «видна» и доступна.
// шаг 2/24 · теория · ~1 мин

Что такое программа для интерпретатора

Аналогия: интерпретатор Python — как человек, читающий кулинарный рецепт вслух и сразу выполняющий каждый шаг, прежде чем перейти к следующему. Он не видит весь рецепт заранее — только текущую строку.

print("Привет, мир")   # эта строка выполнится первой
x = 5                    # эта — второй
print(x)                 # эта — третьей, выведет 5

Код выполняется сверху вниз, строка за строкой (если не встретится команда, которая явно меняет порядок — про них дальше). print() — команда «покажи это на экране», самый частый способ увидеть, что происходит внутри программы.

// шаг 3/24 · теория · ~1 мин

Переменные и типы данных

Аналогия: переменная — как подписанная коробка на складе: на коробке написано имя (age), а внутри лежит содержимое (25). В любой момент можно переложить в ту же коробку что-то другое.

age = 25          # int — целое число
price = 19.99      # float — число с плавающей точкой
name = "Алиса"      # str — строка (текст)
is_ready = True     # bool — логическое значение (True/False)

Python сам определяет тип по значению — не нужно заранее объявлять «эта переменная будет числом». Узнать тип можно через type(age) — вернёт <class 'int'>.

💡Частая ошибка новичка

"5" + "3" даёт "53" (склеивание строк), а 5 + 3 даёт 8 (сложение чисел). Кавычки вокруг числа превращают его в текст — это разные типы, и + для них работает по-разному.

// шаг 4/24 · теория · ~1 мин

Операции над числами и строками

Аналогия: операции над числами — как на калькуляторе, только добавляется пара специфичных для программирования: // (целочисленное деление, отбрасывает остаток) и % (остаток от деления) — та самая операция, что уже встречалась в уроке 2.2 для разбора числа по цифрам.

7 / 2    # 3.5   — обычное деление
7 // 2   # 3     — целочисленное деление
7 % 2    # 1     — остаток от деления
2 ** 5   # 32    — возведение в степень

Со строками работает конкатенация (+) и повторение (*):

"ha" * 3          # "hahaha"
"Привет" + ", " + "мир"   # "Привет, мир"
// шаг 5/24 · теория · ~1 мин

Условия: if / elif / else

Аналогия: развилка на дороге — если дорога мокрая, едешь медленнее; если сухая — обычная скорость. Условие проверяется один раз, выбирается ровно одна ветка.

age = 17

if age >= 18:
    print("Доступ разрешён")
elif age >= 14:
    print("Нужно согласие родителей")
else:
    print("Доступ запрещён")

Отступы (пробелы в начале строки) в Python — не украшение, а часть синтаксиса: именно они показывают, какой код относится к какой ветке if. Если сбить отступ — код или не запустится, или сработает не так, как задумано.

💡Сравнение и логика

== сравнивает значения (5 == 5 → True), = присваивает значение — это разные операторы, спутать их с непривычки легко. and, or, not комбинируют условия: age >= 14 and age < 18.

// шаг 6/24 · теория · ~2 мин

Циклы: for и while

Аналогия: for — как обход всех писем в почтовом ящике по одному, пока письма не кончатся. while — как «продолжай грести, пока не доплывёшь до берега»: условие проверяется перед каждым повтором, и число повторов заранее неизвестно.

for i in range(5):        # 0, 1, 2, 3, 4
    print(i)

range(5) — не список, а специальный «генератор последовательности чисел», который выдаёт числа от 0 до 4 включительно (то есть ровно 5 штук, но последнее число на единицу меньше аргумента) — эта особенность «начинается с 0, заканчивается перед указанным числом» встречается в Python постоянно, в том числе в срезах списков чуть ниже.


fruits = ["яблоко", "банан", "вишня"]
for fruit in fruits:
    print(fruit)

count = 0
while count < 3:
    print(count)
    count += 1             # без этой строки цикл никогда не закончится

for используют, когда заранее известно, по чему проходить (диапазон чисел, список, строка). while — когда конец заранее неизвестен и зависит от условия, которое может измениться в любой момент.

// шаг 7/24 · теория · ~1 мин

Списки (list)

Аналогия: список — как полка с пронумерованными ячейками, где нумерация начинается с 0, а не с 1. Можно достать содержимое конкретной ячейки, добавить новую или убрать существующую.

numbers = [10, 20, 30, 40]

numbers[0]        # 10   — первый элемент
numbers[-1]        # 40   — последний элемент
numbers[1:3]       # [20, 30]  — срез: со второго по третий (не включая 4-й)
# общий вид среза: список[начало:конец] — включает элемент "начало",
# но не включает элемент "конец", ровно как и range() выше

numbers.append(50)  # добавить в конец → [10, 20, 30, 40, 50]
numbers.remove(20)  # удалить значение 20 → [10, 30, 40, 50]
len(numbers)         # 4  — количество элементов

Списки изменяемы (mutable) — можно менять содержимое той же самой коробки, не создавая новую. Списки уже встречались во всех уроках 2.2–2.5 — это одна из самых часто используемых структур в Python вообще.

// шаг 8/24 · теория · ~1 мин

Словари (dict)

Аналогия: словарь — как настоящий бумажный словарь: не по номеру страницы ищешь слово, а по самому слову (ключу) находишь его значение (перевод).

person = {"name": "Алиса", "age": 25}

person["name"]        # "Алиса"
person["city"] = "Москва"   # добавить новую пару ключ-значение
person.get("job", "не указано")   # безопасное чтение: вернёт "не указано", если ключа нет

for key, value in person.items():
    print(key, "→", value)

Ключом словаря может быть почти что угодно неизменяемое (строка, число), значением — вообще что угодно, включая другой словарь или список. JSON, который встречался в уроке 2.2 — это ровно словари и списки, только записанные текстом.

// шаг 9/24 · теория · ~2 мин

Кортежи и множества

Аналогия: если список — полка, куда можно доложить и откуда можно убрать, то кортеж — запаянная упаковка: содержимое видно, но поменять его нельзя. А множество — мешок, где каждый предмет встречается ровно один раз, и порядок в нём не имеет значения.

point = (10, 20)          # кортеж (tuple) — неизменяемый
point[0]                   # 10 — читать можно
# point[0] = 5             # TypeError — менять нельзя

tags = {"linux", "devops", "linux"}   # множество (set)
print(tags)                             # {'linux', 'devops'} — дубликат исчез
tags.add("python")
"linux" in tags                          # True — проверка за постоянное время

Кортеж нужен там, где набор значений не должен меняться: координаты, пара «ключ-значение», возврат нескольких значений из функции (return name, age — это как раз кортеж). Ещё одно практическое отличие: кортеж можно использовать как ключ словаря, а список — нельзя, потому что ключ обязан быть неизменяемым.

Множество решает две задачи. Первая — убрать дубликаты одной операцией: unique = set(my_list). Вторая, более важная — быстрая проверка принадлежности. Поиск x in list перебирает список целиком, а x in set находит ответ мгновенно независимо от размера. На списке в миллион элементов разница видна невооружённым глазом.

a = {1, 2, 3}
b = {3, 4, 5}
a & b        # {3}        — пересечение: что есть в обоих
a | b        # {1,2,3,4,5} — объединение
a - b        # {1, 2}     — разность: что есть в a, но нет в b

Эти операции пригодятся, например, чтобы сравнить список установленных пакетов с требуемым и получить «чего не хватает» одной строкой.

// шаг 10/24 · теория · ~1 мин

Списковые включения (comprehensions)

Аналогия: вместо того чтобы диктовать «возьми пустую корзину, обойди все яблоки, каждое проверь, подходящие положи в корзину», сказать одной фразой: «корзина из всех спелых яблок».

# было
squares = []
for n in range(10):
    squares.append(n ** 2)

# стало
squares = [n ** 2 for n in range(10)]

# с условием
even = [n for n in range(20) if n % 2 == 0]

# работает и для словарей, и для множеств
lengths = {word: len(word) for word in ["ab", "cde"]}
unique_first = {word[0] for word in ["apple", "avocado", "banana"]}

Читается справа налево от for: «для каждого n из range(10) — взять n ** 2». Конструкция настолько распространена в Python, что незнание её сразу выдаёт новичка при чтении чужого кода.

⚠️Когда не надо

Включения хороши для одной простой операции. Как только внутрь просится второе условие, вложенный цикл или вызов на три строки — обычный цикл читается лучше. Правило простое: если строку нельзя прочитать вслух за один раз, разворачивай обратно в цикл.

// шаг 11/24 · теория · ~2 мин

Функции

Аналогия: функция — как кофемашина: один раз настраиваешь рецепт внутри, а потом просто нажимаешь кнопку (вызываешь функцию по имени) сколько угодно раз, не переписывая рецепт заново.

def greet(name):
    return f"Привет, {name}!"

message = greet("Алиса")
print(message)     # Привет, Алиса!

def add(a, b=10):        # b=10 — значение по умолчанию, если не передали
    return a + b

add(5)        # 15  (b взялось по умолчанию)
add(5, 3)     # 8

return — команда «отдать результат наружу и закончить работу функции». Функция без return всё равно отработает, но результат её работы будет None — специальное значение «ничего».

Строка f"Привет, {name}!" — это f-строка (сокращение от formatted string): буква f прямо перед открывающей кавычкой говорит Python, что внутри такой строки фигурные скобки { } — это не обычный текст, а место, куда нужно подставить значение переменной. Без буквы f фигурные скобки просто напечатались бы буквально, как есть. Это самый удобный способ вставлять значения переменных прямо внутрь текста, не склеивая строку вручную через +.

💡Зачем вообще нужны функции

Если один и тот же код нужен в нескольких местах программы — не копируешь его несколько раз, а оформляешь как функцию и вызываешь по имени. Изменить логику потом придётся только в одном месте.

// шаг 12/24 · теория · ~1 мин

Область видимости переменных

Аналогия: переменная внутри функции — как разговор в закрытом кабинете: то, что обсуждали внутри, снаружи не слышно, если специально не вынести решение наружу через return.

def calculate():
    result = 42     # локальная переменная — существует только внутри функции
    return result

calculate()
print(result)   # NameError: result не существует за пределами функции

Переменные, объявленные внутри функции, называются локальными — они «исчезают», как только функция завершила работу. Переменные вне всех функций — глобальные, видны отовсюду в файле. Хорошая практика — не полагаться на глобальные переменные внутри функций, а передавать нужные значения как аргументы.

// шаг 13/24 · теория · ~1 мин

Классы и объекты — ООП с нуля

Аналогия: класс — это чертёж дома, а объект — конкретный построенный по этому чертежу дом. По одному чертежу можно построить сколько угодно домов, и у каждого будет своя мебель (свои данные), но одинаковая планировка (одинаковые методы).

class Dog:
    def __init__(self, name, age):
        self.name = name     # атрибут — данные, принадлежащие конкретному объекту
        self.age = age

    def bark(self):          # метод — функция внутри класса
        return f"{self.name} говорит: Гав!"

rex = Dog("Рекс", 3)     # создание объекта (экземпляра) класса Dog
buddy = Dog("Бадди", 5)

print(rex.bark())        # Рекс говорит: Гав!
print(buddy.name)        # Бадди

__init__ — специальный метод, который вызывается автоматически при создании объекта (Dog("Рекс", 3)) — он настраивает начальное состояние. self — это ссылка на «текущий конкретный объект»: именно поэтому у rex и buddy разные name, хотя оба созданы из одного класса Dog. Классы уже активно использовались в уроке 2.3, 2.4 и 2.5 — там, где заводился Enemy, Status, GameStorage.

// шаг 14/24 · теория · ~1 мин

Импорт модулей

Аналогия: модуль — это готовая книга рецептов, написанная кем-то другим (или тобой самим в другом файле). Вместо того чтобы изобретать рецепт заново, ты просто открываешь нужную книгу и берёшь готовый рецепт.

import random
random.randint(1, 10)      # случайное число от 1 до 10

from itertools import combinations   # взять только одну конкретную вещь из модуля
combinations([1, 2, 3], 2)

import module даёт доступ ко всему модулю через точку (random.randint), а from module import x достаёт из модуля что-то одно по имени — так короче, если нужна ровно одна функция. Оба варианта уже встречались в уроках 2.2–2.5 (import json, from itertools import combinations, from enum import Enum).

// шаг 15/24 · теория · ~3 мин

Ошибки и исключения


Аналогия: исключение — как сработавшая пожарная сигнализация: программа останавливает обычный ход дел и ищет того, кто готов взять ситуацию на себя. Не нашла — здание эвакуируется целиком, то есть программа падает.

try:
    with open("config.json") as f:
        data = json.load(f)
except FileNotFoundError:
    print("Файл конфигурации не найден, беру значения по умолчанию")
    data = {}
except json.JSONDecodeError as e:
    print(f"Конфиг повреждён: {e}")
    raise                      # пробросить дальше — пусть падает
else:
    print("Конфиг прочитан успешно")
finally:
    print("Эта строка выполнится в любом случае")

Четыре блока с разными ролями. В try кладут только рискованную строку — чем меньше кода внутри, тем точнее понятно, что именно упало. except ловит конкретный тип ошибки. else выполняется, только если ошибки не было. finally — всегда, независимо ни от чего; здесь закрывают файлы, соединения и снимают блокировки. Прямой аналог trap ... EXIT из 1.3 Bash.

Типы ошибок, которые встретятся сразу: FileNotFoundError (нет файла), KeyError (нет ключа в словаре), IndexError (индекс за пределами списка), ValueError (значение неподходящее, например int("привет")), TypeError (операция над несовместимыми типами), ZeroDivisionError.

Своё исключение возбуждают через raise:

def set_threshold(value):
    if not 0 <= value <= 100:
        raise ValueError(f"Порог должен быть от 0 до 100, получено {value}")
🛑Голый except — худшее, что можно написать
try:
    do_something()
except:          # ✘ ловит вообще всё, включая твои же опечатки
    pass          # ✘ и молча их проглатывает

Такая конструкция превращает падение с понятным сообщением в тихую поломку, которую потом ищут часами. Она же поймает KeyboardInterrupt и не даст остановить программу с клавиатуры. Лови конкретный тип; если действительно нужно поймать широко — хотя бы except Exception as e и обязательно залогируй e, а не глотай.

В контексте DevOps это та же ловушка, что bash без set -e: скрипт с проглоченной ошибкой отчитается кодом 0, и пайплайн будет зелёным при сломанном результате.

// шаг 16/24 · теория · ~3 мин

Работа с файлами

Аналогия: открыть файл — как взять книгу в библиотеке: пока она у тебя, её не может взять никто другой, и вернуть её нужно обязательно, даже если ты передумал читать.

# чтение целиком
with open("report.txt", encoding="utf-8") as f:
    content = f.read()

# построчно — так читают большие файлы, не загружая их в память целиком
with open("/var/log/app.log", encoding="utf-8") as f:
    for line in f:
        if "ERROR" in line:
            print(line.strip())

# запись
with open("result.txt", "w", encoding="utf-8") as f:
    f.write("готово\n")

# дописать в конец, не стирая
with open("result.txt", "a", encoding="utf-8") as f:
    f.write("ещё строка\n")

Конструкция with — главное, что нужно усвоить: она гарантированно закрывает файл при выходе из блока, даже если внутри произошла ошибка. Открывать файл без with можно, но тогда закрывать придётся вручную, и при исключении файл останется открытым. Незакрытые файлы — источник утечки дескрипторов, той самой, из-за которой в 1.1 Linux место на диске не возвращалось после удаления.

Режимы: "r" — чтение (по умолчанию), "w" — запись с полной перезаписью, "a" — дописать в конец, "x" — создать, но упасть, если файл уже есть.

Параметр encoding="utf-8" стоит писать всегда. Без него Python берёт кодировку системы, и код, работающий на Linux, ломается на Windows — ровно тот класс ошибок, который потом невозможно воспроизвести.

Для путей удобнее современный pathlib, а не склеивание строк:

from pathlib import Path

config = Path("/etc/myapp") / "config.json"    # правильные разделители на любой ОС
if config.exists():
    text = config.read_text(encoding="utf-8")

JSON — формат, с которым в DevOps сталкиваешься постоянно (ответы API, конфиги, вывод многих утилит):

import json

data = json.loads('{"name": "app", "port": 8080}')   # из строки в словарь
data["port"]                                            # 8080
text = json.dumps(data, indent=2, ensure_ascii=False)    # обратно в строку, читаемо
// шаг 17/24 · теория · ~2 мин

Скрипт целиком: точка входа и аргументы

Аналогия: if __name__ == "__main__" — как надпись «главный вход» на здании: файл можно и импортировать как библиотеку через боковую дверь, и запустить напрямую через главный вход, и поведение должно различаться.

#!/usr/bin/env python3
"""Проверяет занятость диска и сообщает, если превышен порог."""

import argparse
import shutil
import sys


def check_disk(path: str, threshold: int) -> int:
    usage = shutil.disk_usage(path)
    percent = usage.used / usage.total * 100
    print(f"{path}: занято {percent:.1f}%")
    return 0 if percent < threshold else 1


def main() -> int:
    parser = argparse.ArgumentParser(description="Проверка занятости диска")
    parser.add_argument("path", help="точка монтирования")
    parser.add_argument("-t", "--threshold", type=int, default=80,
                        help="порог в процентах (по умолчанию 80)")
    args = parser.parse_args()

    return check_disk(args.path, args.threshold)


if __name__ == "__main__":
    sys.exit(main())

Разбор того, что здесь важно. Строка if __name__ == "__main__": означает «выполнять это, только если файл запущен напрямую, а не импортирован». Без неё при импорте твоего файла в другой скрипт весь код тут же выполнится — редко то, что нужно.

sys.exit(main()) передаёт наружу код завершения, ровно тот же механизм, что в bash (1.3 Bash, §1): 0 — успех, ненулевое — проблема. Именно его читает systemd, cron и CI-пайплайн.

argparse — стандартный разбор аргументов командной строки, прямой аналог getopts. Он сам генерирует справку по -h, проверяет типы и ругается на недостающие аргументы. Простой sys.argv тоже существует, но argparse бесплатно даёт всё то, что иначе пришлось бы писать руками.

Двоеточия в def check_disk(path: str, threshold: int) -> int: — аннотации типов. На выполнение они не влияют, но объясняют читателю и редактору, что функция принимает и что возвращает. В рабочих проектах их пишут почти всегда.

venv и pip — окружение проекта


Аналогия: виртуальное окружение — отдельный ящик с инструментами под конкретный проект вместо одной общей свалки в гараже.

Проблема, которую это решает: проекту А нужна библиотека версии 2.25, проекту Б — 2.31. Если ставить обе в системный Python, вторая установка сломает первый проект. Виртуальное окружение даёт каждому проекту свой изолированный набор пакетов.

python3 -m venv .venv                # создать окружение в папке проекта
source .venv/bin/activate             # войти — в приглашении появится (.venv)
pip install requests                   # ставится в окружение, не в систему
pip freeze > requirements.txt           # зафиксировать точные версии
pip install -r requirements.txt          # воспроизвести окружение на другой машине
deactivate                                # выйти

requirements.txt — то, ради чего всё это и делается: файл с точными версиями, по которому окружение восстанавливается один в один на любой машине. Он коммитится в репозиторий, а сама папка .venv — никогда (её место в .gitignore, см. 0.1 Git, §5).

⚠️Не ставь пакеты в системный Python

sudo pip install — команда, которую не стоит выполнять почти никогда. Системный Python принадлежит пакетному менеджеру ОС, и подмена его библиотек ломает системные утилиты, которые на них рассчитывают. На свежих Ubuntu и Debian это даже запрещено принудительно: попытка выдаст ошибку externally-managed-environment. Правильная реакция — не искать обход, а создать venv.

Для утилит, которые нужны глобально (например, ansible), есть pipx: он ставит каждую в собственное изолированное окружение и делает доступной из любого места.

Инструменты посовременнее, которые встретятся в вакансиях: poetry и uv решают ту же задачу, но управляют и зависимостями, и окружением из одного файла pyproject.toml. Начинать стоит с venv и pip — их понимание нужно, чтобы разобраться в остальных.

Ловушки, на которых спотыкаются все

Изменяемый аргумент по умолчанию. Самая известная ловушка Python:

def add_item(item, basket=[]):     # ✘ список создаётся ОДИН раз при объявлении функции
    basket.append(item)
    return basket

add_item("яблоко")     # ['яблоко']
add_item("банан")      # ['яблоко', 'банан'] — не то, что ожидалось!

Правильно — def add_item(item, basket=None): и внутри if basket is None: basket = [].

is против ==. == сравнивает значения, is — что это буквально один и тот же объект в памяти. Для чисел и строк is иногда «случайно» работает из-за внутренних оптимизаций, и потом ломается на других данных. Правило: is используют только с None, True и False.

Копирование списка. new = old не создаёт копию — это второе имя того же списка, и изменение через одно имя видно через другое. Копия — new = old.copy() или new = old[:]. Для вложенных структур нужен copy.deepcopy().

Целочисленное деление у отрицательных. -7 // 2 даёт -4, а не -3: Python округляет вниз, а не к нулю. Стоит помнить при работе с координатами и разбиением на страницы.

Сравнение чисел с плавающей точкой. 0.1 + 0.2 == 0.3 даёт False — это не баг Python, а свойство двоичного представления дробей. Сравнивают через допуск: math.isclose(a, b).

// шаг 20/24 · итоги · ~1 мин

Если запомнить только главное

  • Код выполняется построчно сверху вниз, отступы — часть синтаксиса, а не украшение.
  • = присваивает, == сравнивает — это разные операторы.
  • for — когда заранее известно, по чему идти; while — когда конец зависит от условия.
  • Списки и словари — две самые часто используемые структуры данных в Python.
  • Функция принимает аргументы и через return отдаёт результат наружу; переменные внутри неё не видны снаружи.
  • Класс — чертёж, объект — конкретный экземпляр по этому чертежу; self отличает один объект от другого.
  • import — способ переиспользовать чужой (или свой) код без копирования.
  • Кортеж неизменяем и годится в ключи словаря; множество убирает дубликаты и проверяет принадлежность мгновенно.
  • Списковое включение [x for x in ...] заменяет цикл с append — но только пока строка читается вслух за один раз.
  • try/except/else/finally: лови конкретный тип ошибки, finally выполняется всегда. Голый except: pass — худшее, что можно написать.
  • Файлы открывай через with и всегда указывай encoding="utf-8".
  • if __name__ == "__main__" — точка входа; sys.exit(main()) отдаёт код завершения, который читают systemd, cron и CI.
  • argparse — аналог getopts: сам делает справку и проверяет типы.
  • Каждому проекту — свой venv; requirements.txt коммитим, папку .venv — нет. sudo pip install не делаем никогда.
  • Изменяемый аргумент по умолчанию (def f(x=[])) создаётся один раз на всю жизнь функции — используй None.

  • Задания 1 и 3 (venv, CLI с argparse) — каркас утилиты из мини-проекта M2.

Задание 1 — окружение проекта

Создай проект с venv, поставь requests, зафиксируй зависимости в requirements.txt, добавь .venv/ в .gitignore.
Проверка: на чистой машине python -m venv .venv && .venv/bin/pip install -r requirements.txt воспроизводит окружение; pip freeze совпадает с файлом.

Задание 2 — разбор лога

Напиши скрипт, который читает лог nginx построчно (with open), считает запросы по кодам ответа в словаре и печатает топ-5 IP.
Проверка: результат совпадает с awk '{print $9}' access.log | sort | uniq -c. Файл на 1 ГБ обрабатывается без роста памяти (чтение построчно, а не read() целиком).

Задание 3 — CLI с аргументами

Оформи скрипт с if __name__ == "__main__": и argparse: путь к логу обязательный, --top N необязательный. Несуществующий файл — понятное сообщение и код выхода 1, без трейсбека.
Проверка: python logstat.py --help показывает справку, python logstat.py nope.log; echo $? даёт 1.

Задание 4 — класс

Опиши класс Server с полями name, ip, role и методом is_private(), проверяющим, что адрес из приватного диапазона (модуль ipaddress). Загрузи список серверов из JSON.

Воспроизведи и исправь три ловушки из §18: изменяемый аргумент по умолчанию, изменение списка во время итерации, сравнение is вместо == для строк.
