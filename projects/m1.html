M1 — Скрипт подготовки нового сервера

ℹ️Что получится

Bash-скрипт, который за одну команду превращает свежую Ubuntu в аккуратно настроенный сервер: пользователь для работы, SSH только по ключу, файрвол, автообновления безопасности, UTC, синхронизация времени. Повторный запуск ничего не ломает, а результат проверяется отдельным скриптом.

Маленький проект на выходные, но очень показательный: в нём видно, что ты знаешь базовую безопасность сервера и пишешь bash так, как пишут в командах, — со строгим режимом, функциями, проверками и линтером в CI.

Когда делать: после части 1. Время: 1–2 выходных.
Уроки: 1.1 Linux, 1.2 Сети, 1.3 Bash.

Требования

Скрипт

  • bootstrap.sh со строгим режимом, функциями и main "$@" (1.3 Bash, §2 и §4).
  • Параметры через getopts: имя пользователя, путь к публичному ключу, порты, которые нужно открыть, флаг --dry-run.
  • Создание пользователя с правом sudo и SSH-ключом (1.1 Linux, §4 и §11).
  • sshd_config: запрет root и паролей, проверка sshd -t перед перезагрузкой.
  • ufw: запрет входящих по умолчанию, SSH и указанные порты открыты (1.2 Сети, §7).
  • unattended-upgrades, часовой пояс UTC, проверка синхронизации времени (1.1 Linux, §14).
  • Идемпотентность: второй запуск ничего не меняет и сообщает «уже настроено».
  • Логи с отметкой времени в stderr, понятные ошибки, ненулевой код выхода при сбое.

Проверка

  • verify.sh, который проверяет результат и печатает [ OK ] / [FAIL] по каждому пункту.
  • Стенд для проверки: Vagrantfile с чистой Ubuntu (4.1 Compose и Swarm, §3) или любая виртуалка.

Репозиторий

  • GitHub Actions: shellcheck на каждый пуш, бейдж статуса в README.
  • README: что делает скрипт, как запустить одной командой, что именно меняется на сервере и почему.

Готово, когда

  • На чистой виртуалке sudo ./bootstrap.sh -u deploy -k ~/.ssh/id_ed25519.pub настраивает сервер, а verify.sh показывает все [ OK ].
  • Повторный запуск проходит без изменений.
  • ssh root@... и вход по паролю отклоняются.

Что рассказать на собеседовании

  • Почему вход только по ключу и что ещё защищает сервер в первые минуты после создания.
  • Как ты сделала скрипт идемпотентным и как это проверяла.
  • Когда такой скрипт стоит заменить ролью Ansible (4.3 Ansible, §10) — и почему M1 хорошо переписать в роль common в проекте P2.
