M4 — Универсальный Helm-чарт с публикацией

ℹ️Что получится

Переиспользуемый Helm-чарт для типового веб-сервиса: Deployment с пробами, Service, Ingress, HPA, PodDisruptionBudget, ServiceMonitor — всё включается и настраивается через values. Чарт проверяется линтерами и тестовой установкой в кластер kind прямо в GitHub Actions и публикуется в OCI-реестр с версией.

Такой чарт пишут в каждой команде, где больше двух сервисов, — чтобы не копировать манифесты. В портфолио он показывает, что ты разбираешься в шаблонах Helm глубже, чем helm create, и умеешь выпускать инфраструктурный код как продукт с версиями.

Когда делать: после части 5. Время: 1–2 выходных.
Уроки: 5.1 Kubernetes, 5.2 Kubernetes в работе, 5.3 Helm и Kustomize.

Требования

Чарт

  • Deployment: образ, тег, ресурсы, переменные окружения и секреты из values; liveness, readiness и startup-пробы (5.1 Kubernetes, §11–12).
  • Включаемые блоки: ingress.enabled, autoscaling.enabled, pdb.enabled, serviceMonitor.enabled (5.2 Kubernetes в работе).
  • securityContext по умолчанию: не root, read-only корневая файловая система, без лишних capabilities (6.2 DevSecOps, §8).
  • Общие метки и имена через _helpers.tpl (5.3 Helm и Kustomize, §12).
  • values.schema.json — неверный тип значения отклоняется при установке.
  • NOTES.txt с подсказкой, как открыть сервис после установки.

Проверки и выпуск

  • GitHub Actions: helm lint, kubeconform для отрендеренных манифестов, установка в кластер kind с --wait.
  • Публикация в GitHub Container Registry как OCI-чарт при теге v* (5.3 Helm и Kustomize, §14).
  • Таблица параметров в README генерируется helm-docs.
  • Пример: чарт разворачивает shop-api из стартового каркаса.

Готово, когда

  • helm install demo oci://ghcr.io/<ты>/charts/web-service --version 0.1.0 --set image.repository=nginx работает на чистом кластере.
  • Неверный тип в values (replicaCount: "три") даёт понятную ошибку схемы.
  • Пайплайн зелёный, в README есть таблица всех параметров.

Что рассказать на собеседовании

  • Чем универсальный чарт удобен и где его границы: когда сервису нужен свой.
  • Как проверяется чарт до публикации и что ловит kubeconform, чего не ловит helm lint.
  • Почему чарт выпускают с версиями и как сервисы обновляются на новую версию чарта.
