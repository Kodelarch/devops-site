M2 — certwatch: утилита проверки сертификатов

ℹ️Что получится

Консольная утилита на Python: берёт список доменов, проверяет, когда истекает TLS-сертификат каждого, и печатает таблицу или JSON. По коду выхода её удобно ставить в cron или в пайплайн: «всё хорошо», «скоро истекает», «уже истёк или недоступен». Утилита ставится через pip и запускается в Docker.

Истёкший сертификат — самая предсказуемая авария в индустрии (1.2 Сети, §3), так что проект решает настоящую задачу. А по коду видно, что ты умеешь писать на Python аккуратную утилиту: со слоями, тестами без сети и нормальной упаковкой.

Когда делать: после части 2. Время: 1–2 выходных.
Уроки: 1.2 Сети, 2.2 Python для автоматизации, 2.3 Параллельность, 2.4 Архитектура и тесты.

Требования

Утилита

  • certwatch check example.com github.com и certwatch check -f domains.txt — проверка списка доменов.
  • Проверки идут параллельно с ограничением числа одновременных соединений и таймаутом (2.3 Параллельность, §8 и §10).
  • Вывод таблицей (rich) или в JSON (--json) для других программ.
  • Пороги --warn-days 21 --crit-days 7; код выхода 0 / 1 / 2 — как у healthcheck.sh из 1.3 Bash.
  • Недоступный домен не роняет утилиту: он попадает в отчёт с понятной ошибкой.

Код

  • Слои: домен (сертификат, статус, правило порогов) отдельно от сети и вывода (2.4 Архитектура и тесты, §1).
  • Тесты pytest без сети: двойник вместо реального TLS-соединения, parametrize для порогов (2.4 Архитектура и тесты, §8 и §10).
  • ruff и mypy без ошибок.

Упаковка и CI

  • pyproject.toml с точкой входа: после pip install . команда certwatch доступна в терминале.
  • Dockerfile на python:3.13-slim, запуск не от root (3.1 Docker).
  • GitHub Actions: линтер и тесты на каждый пуш, сборка образа и публикация в GitHub Container Registry по тегу v*.
  • README с примером вывода и строкой для cron.

Готово, когда

  • docker run ghcr.io/<ты>/certwatch check github.com работает на любой машине.
  • pytest проходит с выключенным интернетом.
  • Для домена с сертификатом, истекающим через 5 дней, код выхода 2 (проверь на тестовом двойнике).

Что рассказать на собеседовании

  • Почему проверки идут параллельно и как ты ограничила нагрузку.
  • Как тесты проверяют сетевой код без сети.
  • Как утилиту встроить в мониторинг: cron с алертом по коду выхода или экспортёр для Prometheus — и почему для серьёзного мониторинга берут blackbox_exporter (4.5 Наблюдаемость, §4).
